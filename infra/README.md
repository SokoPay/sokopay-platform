# SokoPay infrastructure (Terraform)

Reference infrastructure for the SokoPay backend on AWS, in **af-south-1 (Cape Town)** —
the nearest AWS region to Ghana, chosen for data-residency defensibility with the Bank
of Ghana and the Data Protection Act.

> This is reviewed, not yet applied. It needs AWS credentials and an ACM certificate.
> Review the plan carefully before the first apply.

## What it provisions

| Area | Resource |
|---|---|
| Network | VPC across 2 AZs, public + private subnets, NAT |
| Compute | ECS Fargate cluster; `api` (behind ALB), `worker` (Celery tasks) and `beat` (the single Celery scheduler — exactly one, never overlapping during deploys) |
| Edge | Application Load Balancer, HTTPS (TLS 1.3), HTTP→HTTPS redirect, **WAF** (managed rules + rate limit) |
| Database | RDS **PostgreSQL 16, Multi-AZ**, encrypted, 14-day backups, deletion protection |
| Cache/queue | ElastiCache **Redis** (primary + replica, encryption in transit & at rest) — cache, OTP store, Celery broker |
| Images | ECR repository, scan-on-push, immutable tags |
| Secrets | Secrets Manager (app config), KMS key with rotation |
| Storage | S3 bucket for KYC docs — private, versioned, KMS-encrypted |
| Autoscaling | `api`: 2–10 tasks on CPU (60%) and ALB requests per task; `worker`: 1–4 on CPU; `beat`: fixed at 1 — `autoscaling.tf` |
| HA | NAT: one shared (default) or one per AZ (`single_nat_gateway = false`) |
| DR (opt-in) | Cross-region RDS automated-backup replication + S3 cross-region replication of every docs version, re-encrypted with a DR-region KMS key — `dr.tf`, off unless `enable_dr = true` |

The app follows 12-factor config: every secret is injected into the ECS tasks from
Secrets Manager at runtime, matching `backend/config/settings/prod.py`. Nothing secret
is in the image or in Terraform state's plaintext (DB password and keys are generated by
`random_password`).

## First-time apply

```bash
cd infra
cp terraform.tfvars.example terraform.tfvars   # fill in

terraform init
terraform apply -target=aws_ecr_repository.backend   # create the repo first

# Build & push the backend image:
#   aws ecr get-login-password --region af-south-1 | docker login --username AWS --password-stdin <ecr-url>
#   docker build -t <ecr-url>:<tag> ../backend && docker push <ecr-url>:<tag>
# Set container_image in terraform.tfvars, then:

terraform apply
```

After apply: run database migrations once (e.g. a one-off ECS task or
`manage.py migrate`), create the first staff superuser, and point DNS at the
`alb_dns_name` output.

## Disaster recovery

**Decision needed before enabling.** AWS has only one region in Africa (Cape Town), so
any cross-region copy leaves the continent. `dr_region` defaults to `eu-west-1`
(Ireland). Confirm the data-residency position with BoG and counsel, then set
`enable_dr = true`.

Targets: **RPO < 1 hour** (RDS backups and S3 objects replicate continuously),
**RTO < 4 hours**.

Recovery runbook (outline — rehearse quarterly and record the drill for BoG):
1. Declare the incident; freeze deploys.
2. In the DR region, restore RDS from the replicated automated backups to the latest
   restorable time.
3. Apply this stack in the DR region (`region = <dr_region>`), pointing it at the
   restored database and the replicated docs bucket.
4. Update the app secret's `DATABASE_URL`, run a ledger-integrity check
   (`apps.ledger.tasks.verify_ledger_integrity`) and a reconciliation run before
   reopening to traffic.
5. Repoint DNS at the DR ALB.
