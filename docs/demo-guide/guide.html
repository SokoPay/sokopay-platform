1. What has been built

SokoPay is one backend (Django, PostgreSQL), three phone apps (Flutter, Android and iOS), two web portals, public payment pages and a USSD channel. Every regulated feature is built and switched on by the Bank of Ghana licence held (PSP Standard, then Medium, Enhanced, then DEMI).

1.7 Under the hood

Money

  • Double-entry ledger in pesewas: the books always sum to zero.
  • Idempotent; row locks proven on PostgreSQL.
  • Reserve, send, resolve for every payout. Ambiguous outcomes are never refunded blindly.
  • Settlement with maker-checker, refunds, disputes with settlement holds, bulk payouts.
  • Configurable fees and agent commissions, with two-person approval.
  • Safeguarding check and daily reconciliation.

Compliance and security

  • Licence gate per capability.
  • KYC tiers using Bank of Ghana limits.
  • AML monitoring rules, sanctions and PEP screening, STR with four eyes, large transaction reports, no tipping off.
  • Encryption, Argon2, revocable tokens, SIM-swap protection.
  • 2FA and rate limits. Append-only audit log. Request IDs.
  • 27 security findings fixed.

Integrations (ready for partners)

  • Payment rail: Korba or Nsano, one partner, certification gate.
  • Billers, telcos, GhIPSS, NIA identity, SMS (Hubtel, mNotify), push (Firebase).
  • Insurance, lending, savings, investment and pension partners.
  • Cross-border (Onafriq, Brij), tickets, food, inbound remittances.

Engineering

  • 487 automated backend tests on PostgreSQL. Flutter tests.
  • CI/CD pipelines and Dockerfile.
  • Terraform for AWS (validated), monitoring and alarms, health page.
  • Backup and restore drill (passed).
  • Legal drafts and a six-pillar review in docs/.

2. Setting up the demo

2.1 Start the demo server and load the seed data

  1. Open PowerShell in SokoPay\sokopay-platform\backend.
  2. Run:
    powershell -ExecutionPolicy Bypass -File scripts\demo.ps1
    This builds a fresh demo database (demo.sqlite3), loads all the demo data (manage.py seed_demo), saves the logins to backend\demo-credentials.md, and starts the server on port 8000. Keep this window open: it is also where sign-in codes appear.
  3. Open http://127.0.0.1:8000/dashboard/ in a browser for the portals, and http://127.0.0.1:8000/dev/mock-partner/ for the mock partner (section 11).
The demo runs with the top licence (DEMI) so every feature is on. The script sets this for the demo only, and your normal .env is untouched.

2.2 Where the one-time sign-in codes come from

In the demo no real SMS is sent. Each code is printed in the server window as a line like:

[SMS:console] to=+233244000201 | Your SokoPay code is 482915 ...

Important alerts that fall back to SMS (cash-out requests, PIN reset) also appear here.

2.3 Portal 2FA codes

Every portal account has 2FA switched on. Either add the account's 2FA secret (section 3) to an authenticator app (Google or Microsoft Authenticator: "Enter a setup key", time-based), or print the current code in a second PowerShell window:

$env:DATABASE_URL="sqlite:///demo.sqlite3"; $env:ALLOW_MOCK_INTEGRATIONS="True"
.\.venv\Scripts\python.exe manage.py demo_2fa_code +233200000004

2.4 Install the phone apps

  1. Install Android Studio and create an Android emulator (Device Manager, then any Pixel phone, Android 14 or newer). An emulator is needed because the demo apps reach the demo server at 10.0.2.2:8000, which is the emulator's address for your computer.
  2. Start the emulator, then drag mobile\dist\sokopay-customer.apk, sokopay-agent.apk and sokopay-merchant.apk onto it (or run adb install).
  3. To show several apps at once, start a second emulator, or switch between apps on one.
On a real phone the APKs need a server reachable over HTTPS. Rebuild with --dart-define=API_BASE_URL=https://your-server/api/v1; see mobile\dist\README.md.

2.5 Signing in to an app

  1. Enter the phone number from section 3 (for example 0244000201) and tap Send code.
  2. Type the code from the server window (2.2).
  3. Because demo users already have a PIN, the app asks for it: 428173.
  4. Optional: turn on fingerprint unlock under More, then Security.

  3. Recon: yesterday's run with an amount mismatch, an "ours only" and a "theirs only" break. Open it and resolve each with a note (your name and the time are recorded).
  4. Safeguarding: e-money owed to customers and agents against the trust account balance. Record a new statement balance and run the check. A shortfall raises an alarm.
  5. Returns: pick a month for transactions, customers, e-money, agents, merchants, complaints and AML figures. Download CSV.
  6. Health: live operational numbers (stuck payouts, failed payments, overdue disputes, safeguarding).

8.5 Support (Selorm 0200000008)

  2. You see name, wallet ID, balance, KYC tier, devices and 30 days of activity. If the wallet is on hold, support sees "refer to compliance" but never the AML reason (no tipping off).

10. USSD for basic phones

A real network aggregator sends each screen to /api/v1/ussd/callback. In the demo, simulate it from PowerShell. Each call sends everything typed so far, joined by *:

function ussd($text) { (Invoke-WebRequest -Method Post http://127.0.0.1:8000/api/v1/ussd/callback `
  -Body @{sessionId="demo1"; serviceCode="*713#"; phoneNumber="+233244000201"; text=$text}).Content }
ussd ""            # CON SokoPay  1 Check balance  2 Send ...  4 Cash out at agent ...
ussd "1"           # CON Enter your PIN
ussd "1*428173"    # END Your SokoPay balance is GHS ...
  1. Send: new session (change sessionId), then 2, then 2*0244000202 ("Send to Ama S."), then 2*0244000202*10, then 2*0244000202*10*428173.
  2. Cash out without a smartphone: option 4 opens the cash-out window. After the agent sends the request, dial again: 4 shows "Esi's Kiosk wants to pay you GHS …". Enter the PIN to approve, or 0 to decline.
  3. Other options: airtime (3), mini statement (5), wallet ID (6).

13. Resetting and troubleshooting

SituationWhat to do
Start the demo again from scratchStop the server (Ctrl+C) and run scripts\demo.ps1 again. It deletes demo.sqlite3 and reloads everything.
"Demo data is already loaded"The seed only runs on an empty database. Use the script, which starts fresh.
No sign-in code arrivesLook in the server window for [SMS:console]. Codes expire after a few minutes, and too many requests are rate-limited.
App says it can't connectUse an Android emulator (the apps call 10.0.2.2:8000). Check the server is running and the script set ALLOWED_HOSTS.
2FA code rejectedCheck the computer clock. Generate a fresh code (codes last 30 seconds). Five wrong codes lock for 15 minutes.
"Account is temporarily locked"Five wrong PINs lock the account for a few minutes (security feature).
A payment stays "pending"Approve or decline it on the mock partner page (section 11).
Feature says "not available yet"The licence gate: the demo script runs with DEMI. Outside the script, set SOKOPAY_ACTIVE_LICENCE=DEMI.
